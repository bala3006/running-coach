02 / CHAT CYCLE

One turn

  1. The browser sends a message, session ID, language, and voice preference to FastAPI.
  2. The local embedder encodes the query; hybrid search ranks stored activity and reflection records with vector similarity and FTS5.
  3. For explicit marathon-goal questions, Python returns a deterministic report from recent Strava runs and the training sheet. Other questions add retrieved evidence, conversation history, and available MCP tools to the coach request.
  4. Llama 3.2 responds or requests bounded read-only tools. The host executes registered tools even if the model emits their call payload as text, then saves the final exchange locally.

03 / TRUST BOUNDARIES

What leaves the machine

  • Chat prompts, retrieved training memories, and conversation history go to the configured local Ollama endpoint; no hosted LLM or embedding API is used.
  • Embedding vectors, source records, and FTS indexes remain in local SQLite. The embedding model name is recorded per vector for safe re-indexing.
  • Strava and Google receive their own read-only API requests when the runner syncs activities or the coach calls an integration tool.
  • OAuth access and refresh tokens are stored in the operating system credential store.
  • The app does not call a hosted LLM and exposes no plan-write or sheet-write tools.
  • Run temperature and humidity are stored locally; no route location is sent to a weather service.

04 / DESIGN DECISIONS

Why hybrid local retrieval

  • Embeddings connect meaning across free-text reflections, so “heavy legs” can be found by a question about fatigue.
  • FTS5 preserves exact lookup for dates, distances, weather values, and activity names. Reciprocal-rank fusion combines both retrieval lists.
  • All vectors stay beside their source records in SQLite. If the embedding model is unavailable, keyword retrieval still works.
  • Race projections stay deterministic and show their source run; the model explains the estimate but does not calculate it or promise a result.

Safety boundary

Coach Eklavya provides training guidance, not medical care. It does not diagnose injuries. For concerning symptoms it should advise stopping and seeking professional care. The integrations start read-only, and the model cannot edit your training plan.
